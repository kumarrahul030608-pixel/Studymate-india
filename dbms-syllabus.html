Module 1 — Introduction

Purpose of Database Systems: Store and retrieve organized data efficiently while supporting sharing, security, integrity and recovery.
View of Data: Physical level describes storage, logical level describes the database structure, and view level presents selected information to users.
Data Models: Relational, ER, hierarchical, network and object-oriented models.
Database Languages: DDL defines structure; DML changes data; DQL retrieves data; DCL controls privileges; TCL manages transactions.
Relational Database: Data is represented using tables (relations) containing rows and columns.
Database Architecture: Common three-schema architecture separates external, conceptual and internal views.

Module 2 — Relational Models & Languages

Keys: Super key, candidate key, primary key, alternate key and foreign key identify rows and relationships.
Entity-Relationship Diagram: Models entities, attributes and relationships before implementation.
Relational Algebra: Selection (σ), projection (π), union, difference, Cartesian product and joins.
SELECT name, gpa FROM student WHERE gpa >= 8 ORDER BY gpa DESC;

Module 3 — Relational Database Design

Functional Dependency: X → Y means X determines Y.
Normalization: 1NF removes repeating groups; 2NF removes partial dependency on a composite key; 3NF removes transitive dependency; BCNF strengthens 3NF.
Lossless Decomposition: A decomposition should allow the original relation to be reconstructed without spurious tuples.
SQL: CREATE, ALTER, DROP; INSERT, UPDATE, DELETE; SELECT; GRANT and REVOKE; COMMIT and ROLLBACK.

Module 4 — Query Processing & Optimization

Query processing converts a declarative SQL query into an efficient execution plan. Steps include parsing, translation, optimization and execution.
Selection, projection, joins and relational expressions are evaluated using alternative algorithms. Cost estimation considers I/O, CPU, memory and intermediate result size.
Query optimization chooses a lower-cost execution plan using indexes, join ordering and access paths.

Module 5 — Transactions & Concurrency Control

Transaction: A logical unit of work. ACID properties are Atomicity, Consistency, Isolation and Durability.
Serializability: A concurrent schedule is correct when its effect is equivalent to a serial execution.
Recoverability: Ensures committed transactions do not depend on results of uncommitted transactions.
Locking: Shared locks allow reading; exclusive locks allow writing. Two-phase locking helps ensure conflict serializability.
Deadlock: Transactions wait indefinitely for one another. Prevention, avoidance and detection/recovery are common approaches.
