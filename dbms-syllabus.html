Module 1 — Introduction to Database Systems

1. Data, Database and DBMS

Data is a collection of raw facts, such as roll number, name and marks. A database is an organized collection of related data. A DBMS is software used to create, store, retrieve, update, secure and manage databases.

Easy example: A college database can contain Student, Course, Faculty and Marks tables. MySQL, Oracle and PostgreSQL are examples of DBMS/RDBMS software.

2. Purpose of Database Systems

DBMS reduces unnecessary duplication, provides controlled data sharing, enforces integrity and security, supports concurrent users, provides backup/recovery and makes querying easier than managing independent files.

3. View of Data

Physical level: how data is actually stored. Logical/conceptual level: what data is stored and relationships among it. View/external level: what a particular user is allowed to see.

Data independence: ability to change one level without requiring changes at the next higher level. Physical data independence changes storage details; logical data independence changes the logical schema with minimal effect on external views.

4. Data Models

Relational: tables, rows and columns.
ER: entities, attributes and relationships.
Hierarchical: tree structure.
Network: graph-like records and links.
Object-oriented: objects/classes with data and behavior.
Document: document-oriented data such as JSON.

5. Database Architecture

The three-schema architecture contains external schemas for user views, a conceptual schema for the complete logical database and an internal schema for physical storage. A DBMS also includes query processor, storage manager, transaction manager and authorization/integrity components.

6. Database Languages

DDL: CREATE, ALTER, DROP. DML: INSERT, UPDATE, DELETE. DQL: SELECT. DCL: GRANT, REVOKE. TCL: COMMIT, ROLLBACK, SAVEPOINT.

Module 2 — Relational Model, ER Model & SQL

1. Relational Model

A relation is a table. A tuple is a row, an attribute is a column, and the domain is the allowed set of values for an attribute. Degree = number of attributes; cardinality = number of tuples.

2. Keys

Super key: any attribute set that uniquely identifies a row. Candidate key: minimal super key. Primary key: chosen candidate key. Alternate key: candidate key not selected as primary. Foreign key: attribute referencing a key in another table.

Exam point: Primary key values cannot be NULL and should uniquely identify tuples. Foreign keys maintain referential integrity.

3. ER Model

An entity is a distinguishable object. An attribute describes an entity. A relationship connects entities. Cardinality may be 1:1, 1:N, N:1 or M:N. Attributes may be simple/composite, single-valued/multivalued or derived.

4. Relational Algebra

Selection (σ) filters rows. Projection (π) selects columns. Union (∪) combines compatible relations. Difference (−) finds tuples in one relation but not another. Cartesian product (×) pairs tuples. Join (⋈) combines related tuples. Rename (ρ) changes relation/attribute names.

Example: σ GPA>8(Student) means select students whose GPA is greater than 8.

5. SQL Basics

CREATE TABLE Student (roll_no INT PRIMARY KEY, name VARCHAR(50), major VARCHAR(30), gpa DECIMAL(3,2)); INSERT INTO Student VALUES (10, 'Rahul', 'CSE', 8.50); SELECT name, gpa FROM Student WHERE gpa >= 8 ORDER BY gpa DESC; UPDATE Student SET gpa = 9.00 WHERE roll_no = 10; DELETE FROM Student WHERE roll_no = 10;

6. SQL Joins and Aggregation

SELECT s.name, d.dept_name FROM Student s JOIN Department d ON s.dept_id = d.dept_id; SELECT major, AVG(gpa) AS avg_gpa FROM Student GROUP BY major HAVING AVG(gpa) > 7;

Common joins: INNER, LEFT, RIGHT and FULL OUTER join. Aggregate functions include COUNT, SUM, AVG, MIN and MAX.

Module 3 — Database Design & Normalization

1. Functional Dependency

A functional dependency X → Y means that if two tuples have the same value of X, they must have the same value of Y. X is the determinant. Example: RollNo → StudentName.

2. Anomalies

Poorly designed tables can cause update anomaly (same fact must be changed repeatedly), insertion anomaly (cannot insert a fact without unrelated data) and deletion anomaly (deleting one fact accidentally removes another).

3. Normalization

1NF: atomic values, no repeating groups. 2NF: in 1NF and no partial dependency of a non-key attribute on part of a composite candidate key. 3NF: in 2NF and no transitive dependency of non-key attributes on a key. BCNF: every determinant is a candidate key.

Memory trick: 1NF = atomic, 2NF = no partial dependency, 3NF = no transitive dependency, BCNF = every determinant is a candidate key.

4. Lossless Join & Dependency Preservation

A decomposition is lossless if joining the decomposed relations recreates the original relation without spurious tuples. A decomposition is dependency-preserving if functional dependencies can be enforced using the decomposed relations without reconstructing the original relation.

5. Integrity Constraints

Domain constraint: valid values. Key constraint: uniqueness. Entity integrity: primary key is not NULL. Referential integrity: foreign-key values must match referenced key values or be NULL where permitted.

Module 4 — Query Processing & Optimization

1. Query Processing Steps

A SQL query is parsed and validated, translated into an internal representation, optimized to choose an efficient execution plan, and then executed by the DBMS.

2. Query Evaluation

DBMS can use table scans, index scans, sorting, hashing and different join algorithms. The choice depends on relation size, available indexes, selectivity, memory and estimated I/O cost.

3. Query Optimization

The optimizer compares possible execution plans and selects a low-cost plan. Typical ideas include pushing selections/projections early, choosing efficient join order, using indexes and reducing intermediate results.

4. Indexing

An index is an auxiliary data structure that speeds up data retrieval. B+ trees are widely used for range and ordered searches; hash indexes are useful for equality searches. Indexes improve reads but consume storage and can increase INSERT/UPDATE/DELETE cost.

5. Query Example

SELECT major, COUNT(*) AS students, AVG(gpa) AS avg_gpa FROM Student WHERE gpa >= 7 GROUP BY major ORDER BY avg_gpa DESC;

Module 5 — Transactions, Concurrency & Recovery

1. Transaction

A transaction is a logical unit of database work. It may contain multiple operations but should preserve database correctness.

ACID: Atomicity = all or nothing; Consistency = valid state to valid state; Isolation = concurrent transactions should not improperly interfere; Durability = committed changes survive failures.

2. Transaction States

Typical states are Active → Partially Committed → Committed. If an error occurs, a transaction may move to Failed → Aborted, after which it can be rolled back or restarted.

3. Schedules & Serializability

A serial schedule runs transactions one after another. A concurrent schedule interleaves operations. A schedule is conflict-serializable if its precedence graph is acyclic. A cycle indicates that the schedule is not conflict-serializable.

4. Concurrency Problems

Lost update: one update overwrites another. Dirty read: a transaction reads uncommitted data. Non-repeatable read: the same row gives different values within a transaction. Phantom read: repeated query returns a different set of rows.

5. Locks & Two-Phase Locking

Shared lock (S): read. Exclusive lock (X): write. In two-phase locking (2PL), a transaction has a growing phase where it acquires locks and a shrinking phase where it releases locks. Strict 2PL keeps exclusive locks until commit/abort.

6. Deadlock

Deadlock occurs when transactions wait for resources held by each other. Common approaches are prevention, avoidance, detection and recovery. A wait-for graph cycle can indicate deadlock.

7. Recovery

Recovery restores the database to a consistent state after failure. Log-based recovery records changes; UNDO reverses effects of uncommitted transactions and REDO reapplies effects of committed transactions when necessary. Checkpoints reduce recovery work.

8. TCL Example

START TRANSACTION; UPDATE Student SET gpa = 9.10 WHERE roll_no = 10; SAVEPOINT s1; UPDATE Student SET gpa = 8.90 WHERE roll_no = 11; ROLLBACK TO s1; COMMIT;

⚡ Quick Revision + Important Exam Questions

1. DBMS vs File System?
DBMS provides structured querying, concurrency, security, integrity, backup/recovery and reduced redundancy.
2. What is a primary key?
A chosen candidate key that uniquely identifies each tuple and cannot contain NULL.
3. What is normalization?
A database-design process that reduces redundancy and update anomalies.
4. 1NF, 2NF, 3NF?
Atomic values → no partial dependency → no transitive dependency.
5. What is ACID?
Atomicity, Consistency, Isolation and Durability.
6. What is serializability?
Correctness criterion requiring a concurrent schedule to have an equivalent serial effect.
7. What is a foreign key?
A key/attribute that references a key in another relation and supports referential integrity.
8. What is deadlock?
A state where transactions wait indefinitely for resources held by one another.
Numerical/exam practice: Focus on relational algebra expressions, functional-dependency closure, candidate keys, normalization to 1NF/2NF/3NF/BCNF, lossless decomposition, SQL queries, precedence graphs/serializability, locking schedules and recovery problems.
